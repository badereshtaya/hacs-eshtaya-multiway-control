# Architecture

## Design goals

Eshtaya Multi-Way Control is a local Home Assistant helper integration. It does not talk to Tuya, Zigbee, KNX, Shelly, or any vendor API directly. It coordinates entities that are already exposed to Home Assistant.

The core design goals are deterministic output control, loop prevention, recovery from delayed/cloud state updates, and preserving the physical load state as the authority.

## Group model

Each group contains one **output** and one or more **controllers**.

- The output is the entity physically responsible for the load.
- Controllers represent additional wall controls or event sources.
- A virtual Home Assistant light/switch exposes the group as one logical endpoint.
- Runtime diagnostic entities expose health without requiring the management panel.

## Transaction flow

For a controller-originated command:

1. Normalize the controller transition according to its mode and inversion settings.
2. Acquire the per-group transaction lock.
3. Send the target state to the physical output.
4. Optionally wait for state confirmation and retry according to policy.
5. Commit the desired state only after the output confirms.
6. Synchronize commandable controllers that are configured to reflect state.
7. Publish runtime health/activity updates.

Commands generated by the integration are registered as pending state changes. Matching state-change events are consumed as acknowledgements rather than interpreted as new physical input. This is the primary feedback-loop protection.

## Recovery

- `unknown` and `unavailable` transitions are never treated as user input.
- A restored controller is reconciled to the confirmed desired state when reflection is enabled.
- A restored output uses the configured `adopt` or `enforce` recovery policy.
- Startup protection delays reconciliation while source integrations restore their entities.
- A periodic watchdog is a safety layer; normal control is event-driven.

## Persistence

Configuration and the last confirmed state are stored with Home Assistant's storage helper. The internal storage schema is versioned separately from the Home Assistant Store envelope so future schema changes can be migrated safely.

The integration uses the stable domain `eshtaya_multiway`; its storage key is derived from that domain.

## Frontend

The admin-only sidebar panel communicates with the integration through authenticated Home Assistant WebSocket commands. The bundled JavaScript is served locally by Home Assistant; no external CDN or cloud service is required.

## Privacy

The integration requires no external credentials and makes no direct external network requests. Diagnostics are intentionally reduced and should still be reviewed before sharing publicly.
